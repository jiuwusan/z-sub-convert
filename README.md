# Clash.Meta 订阅转换服务

一个面向 Clash.Meta/Mihomo 的轻量 Node.js 订阅转换服务。它可聚合多个 Clash YAML 订阅，按来源、协议和国家/地区生成代理分组，重命名节点，并组合所选本地模板。

生成配置时自动收集最终 `proxies[].server`，在 `rules` 最前添加去重的代理入口直连规则：域名使用精确 `DOMAIN,入口域名,DIRECT`，IPv4/IPv6 使用 `/32`、`/128` 的 IP 规则并附带 `no-resolve`。包括模板自有节点与聚合订阅节点，已有相同直连规则移到最前而不重复；其他模板规则保留原顺序。使用内置 `DIRECT`，不依赖可手动切换的直连策略组。不主动查询入口域名的 IP，也不修改 DNS、TUN 或节点的 `dialer-proxy` 配置；系统路由或其他设备的 TUN 转发仍需单独配置。

## 订阅管理后台

启动后打开 `http://127.0.0.1:25500/`（也支持 `/admin`）。首次使用直接设置用户名和密码，无需 key；密码须为 8–128 个字符。后续通过用户名、密码登录。账号密码以 scrypt 哈希存储，登录会话有效期为 12 小时，服务重启后重新登录。

后台使用原生 hash 路由，无需额外前端依赖或服务端路径重写。系统订阅、第三方来源、基础模板、nameserver、规则模板分别对应 `#/subscriptions`、`#/sources`、`#/bases`、`#/nameservers`、`#/templates`；支持直接打开、刷新后保留当前页、浏览器前进/后退及新标签页打开。登录、首次初始化和重置账号分别使用 `#/login`、`#/setup`、`#/reset`。未登录访问管理页面时跳转登录，登录后返回原页面；跳转目标仅接受上述管理页。

1. **第三方订阅源**：维护名称、官网（可选）、User-Agent、订阅链接。官网支持 HTTP/HTTPS 地址，可在编辑时修改或清空，修改官网不影响订阅缓存。新增 User-Agent 默认为 `clash-verge/v2.4.5`，后台列表隐藏链接路径、令牌参数及其值。编辑时可查看完整链接。每个来源独立缓存原始节点数据，列表展示缓存状态、最近成功时间和最近更新结果，提供单条“更新”和“全部更新”。
2. **基础模板**：维护名称和 YAML 内容，可在 textarea 编辑或读取本地文件；只检查 YAML 语法，不做业务结构校验。基础模板负责端口、运行模式、其他 DNS 设置等；最终 `dns.nameserver` 和规则三个字段由独立配置替换。
3. **Nameserver**：每条维护名称和单个完整 DNS 地址，例如 `https://dns.google/dns-query#🚀 节点选择`，保留协议、参数和 `#` 后的内容，不限制 DNS 协议。维护地址时需自行确保引用的分组存在于最终配置。
4. **规则模板**：维护名称和 YAML 内容，支持 textarea 编辑或读取文件。仅此类做业务结构校验：`proxies`、`proxy-groups`、`rules` 须为数组，并包含“🚀 节点选择”“🔰 故障转移”分组及其 `proxies` 数组。组装时只取这三个顶层字段，其他字段不覆盖基础模板。
5. **系统订阅**：输入名称、多选第三方来源、单选基础模板、单选规则模板、多选 nameserver。可勾选“使用订阅源 nameserver”，手动选择仍可用，作为全部来源均未提供 nameserver 时的备用。被引用的来源、基础模板、规则模板和手动/备用地址不能删除；删除系统订阅会撤销其链接。

新空数据目录从 `TEMPLATE_PATH`（默认 `prds/template.yaml`）提取默认基础模板、每个默认 nameserver 地址和默认规则模板；后续启动不覆盖维护内容。系统订阅按“基础模板 → nameserver → 规则三个字段 → 来源节点聚合与分组”组装，修改任一配置在下次访问立即应用，不重新拉取仍有效的来源缓存。

系统订阅可勾选“移除‘故障转移’组”，默认不勾选。仅从该订阅的最终配置中移除顶层 `🔰 故障转移`，各国家/协议分组继续保留。“🚀 节点选择”对它的引用展开为原成员；AI 平台等其他组中的引用改为“🚀 节点选择”并去重，不自动引入国家分组，规则/子规则目标、DNS 地址片段和节点/provider override 的 `dialer-proxy` 引用改为 `🚀 节点选择`，避免常见引用失效。只修改生成结果，原规则模板及模板下载不变，保存规则模板仍要求两个必要分组。公开订阅和后台系统下载均应用选项，切换后无需更新来源缓存；旧记录默认保留故障转移组。

新增/编辑系统订阅时可配置“国家分组类型”、“国家分组测试间隔（秒）”和“国家分组测试 URL”，统一应用于该订阅自动生成的国家分组，支持 `fallback`、`url-test`、`select`、`load-balance`。默认及旧记录缺字段时使用 `fallback`、`http://www.gstatic.com/generate_204`，自动测试间隔默认 305 秒，可配置为 1–86400 的整数秒；旧记录缺少间隔时使用 305 秒。`select` 不输出 `url`/`interval`，填写的 URL 和间隔仍保存供切回自动类型使用；`load-balance` 输出 `strategy: consistent-hashing`（[Mihomo 文档](https://wiki.metacubex.one/config/proxy-groups/load-balance/)）。对应 API 字段为 `countryGroupType`、`countryTestUrl`、`countryTestInterval`，更新时省略则保留原值；测试 URL 须为不带账户和控制字符的有效 HTTP/HTTPS 地址。配置持久化并参与生成指纹，公开订阅和后台下载一致；不修改模板既有分组，也不更新有效来源缓存。

勾选“使用订阅源 nameserver”后可多选 DNS 来源，仅限当前订阅已关联的源。不选时聚合全部关联来源；选中时仅合并所选来源的 `dns.nameserver`，按关联源顺序去重，所选源均未提供时使用手动备用项，不会改用未选来源。关闭来源模式后手动地址生效，DNS 来源选择保留。旧记录默认聚合全部来源；节点和套餐仍聚合全部关联源，来源缓存及更新规则不变。

系统订阅按“来源＋协议＋国家”分别生成分组，单源也包含来源名称，例如组 `🇺🇸 A SS 美国`、节点 `🇺🇸 A 美国 01`。同国家不同源不再合并。生成组追加顺序为“国家优先级 → 订阅关联来源顺序 → 协议优先级”，例如 `A 美国、B 美国、A 日本、B 日本`；国家优先级保持美国、日本、新加坡在前。节点选择、故障转移及最终分组数组采用相同顺序，模板既有成员保留原序。重名来源及生成名与模板名称碰撞时加后缀消歧。改来源名称后，下次生成立即生效，无需更新有效来源缓存；第三方源预览和下载仍保留原文。

第三方订阅中的顶层 `hosts` 自动合并到生成的订阅，系统订阅及 `/sub?url=...` 转换入口均支持。按域名合并，冲突时模板已有值优先，其次取订阅关联来源顺序中的第一个值；保留字符串、地址数组、别名及通配域名。未提供或不是映射的来源 `hosts` 忽略，不额外生成空字段。系统订阅直接读取完整来源缓存，无需额外请求；旧版仅节点缓存需成功更新一次后才能补齐 `hosts`。

来源配置了 `dns.proxy-server-nameserver` 时，为该来源保留节点的 `server` 域名自动生成 `dns.proxy-server-nameserver-policy`（IP 节点跳过），使不同来源节点使用各自 DNS。`hosts` 中节点域名关联的别名目标也会生成策略。来源 DNS 地址为 `127.0.0.1:端口`（包括 UDP/TCP/TLS/HTTPS URL）时，替换为同一来源的 `dns.nameserver`，备用中也排除本地地址，混合列表保留外部地址并去重；没有可用地址则跳过自动策略。来源已有 `proxy-server-nameserver-policy` 和 `nameserver-policy` 也会导入，仅删除其中指向 `127.0.0.1` 的地址，删空的条目不导入。模板同名策略优先，多个来源的同名策略按关联顺序取第一个；显式节点策略（含匹配的通配策略）优先于自动生成策略。模板的本地 DNS 配置保持原样。

两个转换入口均支持来源 DNS 策略，复用完整来源缓存，无额外请求，与 nameserver 来源选择开关独立。最终 `dns.proxy-server-nameserver` 完全保留模板配置：不追加来源地址，也不在缺失、为空数组或 null 时自动补齐；来源 DNS 仅参与对应 policy 的生成和合并。仅节点的旧版缓存缺少来源 DNS，需成功更新后补齐。

导入 DNS 地址中的 `#节点名` 引用随保留节点的重命名同步更新，其他 DNS 参数保留。来源独有的策略组不会自动导入，地址引用的策略组仍须在最终模板中存在。

新增/编辑系统订阅时，已选来源显示“上移 / 下移”，可调整当前订阅的来源顺序；首尾方向按钮禁用。新勾选来源追加到已选队尾，取消后重新勾选也追加到末尾。nameserver 来源标签随顺序联动并保留 DNS 选择。保存后按此顺序生成同国家分组、聚合节点和来源 nameserver；取消编辑不保存，其他系统订阅不受影响，无需更新有效缓存。

新增/编辑系统订阅时可勾选“自定义国家”，默认关闭并加入全部上游节点。开启后从已选来源解析国家标签（国旗、名称、节点数量），至少选择一项；未识别国家的节点归为“其他”。按节点名称识别，不查询 IP 地理位置。所选国家随订阅保存，后续公开链接与后台下载均持续过滤节点及生成分组；关闭后恢复全部，保留原选择。来源暂时不含已选国家时显示“暂无节点”，不会自动删除白名单；所有所选国家均无节点时明确报错，不自动放开为全量。模板自有节点不受影响。API 字段为 `customCountries`（默认 false）、`countryCodes`（默认 []，如 `["US", "JP", "OTHER"]`），编辑省略字段保留原值，旧记录默认全量。

国家候选使用需登录和 CSRF 校验的 `POST /api/subscriptions/countries`，正文为 `{ "sourceIds": ["来源ID"] }`，返回国家代码、名称、旗帜、节点数量及缓存是否过期；不返回节点连接信息。仅开启筛选、变更来源或点击“重新解析”时请求，复用来源缓存和原有更新规则：有效缓存不额外拉取，自动来源无缓存/过期时按需更新，手动来源无缓存时提示先更新；旧缓存仍可用时会提示。筛选不会修改共享来源缓存、原有国家/协议排序或其他订阅。

系统订阅可勾选“偶数节点前置”，默认关闭，旧记录缺少该字段也按关闭处理。关闭时各来源/国家/协议分组内保留源内节点顺序，取消原先固定交换前两项的行为；开启后按生成编号，将偶数排在奇数前面，两部分各自保持原序，例如 `02、04、06、01、03、05`。编号按同一来源、同一国家跨协议连续递增，顶层节点顺序、分组排序及来源缓存不变。每份订阅独立配置，公开链接与后台下载均生效。旧 `/sub?url` 无后台来源名称，继续使用不带来源的命名及协议优先排序。

基础模板和规则模板列表提供“下载”，导出当前保存的 YAML 原文，保留注释、格式和换行，不与其他配置或来源节点组装。文件名为 `名称-下载时Unix毫秒时间戳.yaml`。下载需要后台登录，不触发第三方请求。

手动 DNS 模式至少选择一个地址。来源 DNS 模式按所选来源顺序读取完整缓存正文中的 `dns.nameserver`，忽略非数组、空值及非单行字符串地址，按完整地址去重；只要任一来源提供可用地址，就只使用来源地址，不混入手动备用。所有来源均未提供时，改用手动选择项；两者均无可用地址时返回 HTTP 422 明确提示。来源 nameserver 与正文、套餐共享同一次 GET 的 2 小时缓存，无额外探查请求。

复制出的链接格式为 `/sub?key=xxx`，无需后台登录即可供客户端使用。每条订阅有独立随机 key，修改配置、更新、重启或重置账号均不改变链接。

来源列表提供“预览”，登录后可查看第三方返回的完整订阅原文（包括 DNS、分组、规则、其他配置和注释，未套用系统订阅模板），并复制内容。缓存保留原文格式和换行，不通过节点重新拼装。预览展示节点数量、缓存状态和最近成功更新时间；无缓存时提示先“更新”，过期或配置变更后保留的完整旧缓存仍可查看。旧版本仅保存节点的缓存仍可用于系统订阅转换，预览会提示更新一次以取得完整结果。打开预览不拉取第三方订阅。“刷新”只重新读取列表，“更新 / 全部更新”才主动更新来源缓存。

来源列表、来源预览弹窗和系统订阅列表均提供“下载”。文件名为 `名称-下载时Unix毫秒时间戳.yaml`，支持中文名称；不适合文件名的字符自动替换，超长名称适当截短。来源下载读取完整缓存原文，不触发上游请求，无缓存或只有旧版节点缓存时提示先更新；系统订阅下载生成所选本地模板的完整配置，缓存缺失或过期时按既有规则更新来源。直接访问 `/sub?key=...` 也使用系统订阅名称作为下载文件名。后台下载接口需要登录。

### 系统订阅调用记录

系统订阅列表的“记录”按钮可查看最近 3 天（滚动 72 小时）的调用时间、GET/HEAD 方法、来源 IP、User-Agent、HTTP 状态码、服务端处理耗时和失败原因，每页 50 条，支持刷新、上一页和下一页。只记录公开 `/sub?key=...` 链接能够归属到系统订阅的请求，成功和失败都会记录；后台下载、非法 key 以及旧 `/sub?url=...` 兼容入口不计入。不保存订阅 key、完整请求 URL 或订阅正文。来源 IP 为直接连接地址，反向代理部署时可能是代理服务器的 IP，不默认信任 `X-Forwarded-For`。

记录按订阅和 UTC 日期以 JSONL 文件追加保存在 `DATA_DIR/call-records`，不重写订阅配置，重启后可查看。没有 200 条上限；查询始终过滤 72 小时外的数据，启动时及每 15 分钟清理磁盘过期记录。删除订阅时同步清理对应文件，日志写入失败不会改变订阅响应。后台查询接口为 `GET /api/subscriptions/:id/calls?page=1`，需要登录。备份整个 DATA_DIR 时会一并包含调用记录。

### 第三方来源缓存更新记录

第三方来源列表的“记录”按钮可查看最近 3 天（滚动 72 小时）的实际缓存更新，包括更新时间、更新方式（按需更新 / 手动更新 / 全部更新）、本次使用的 User-Agent、结果、耗时和失败原因。每页 50 条，支持刷新和翻页，不限制总条数。按需更新包括访问或下载系统订阅时因来源无缓存、过期或配置失效触发的实际拉取；命中缓存、打开预览和下载已有来源缓存不计入。并发更新合并时只记一次，更新方式以首次发起的作业为准。

记录独立追加保存在 `DATA_DIR/source-refresh-records`，与系统调用记录隔离，不保存完整来源 URL、令牌或订阅正文。日志写入失败不影响更新结果，更新失败仍保留旧缓存。重启保留，启动及每 15 分钟清理过期记录，查询严格过滤 72 小时。删除来源时同步清理记录，配置修改期间的旧作业失败会使用当次 User-Agent 记录。查询接口为 `GET /api/sources/:id/updates?page=1`，需要登录；无需更换现有 v3 数据目录。

### 缓存规则

- 缓存以**第三方订阅源**为单位保存完整原始订阅文本，多个系统订阅复用；生成系统订阅时从原文提取节点，仍使用所选本地模板，不缓存转换后的系统订阅成品。
- 保存配置不拉取。访问系统订阅时，只有无缓存、配置失效或超过 **2 小时**的来源才拉取，其他来源直接复用缓存。有效期从该来源最近成功时间计算，没有定时拉取。
- 来源列表的单条“更新”和“全部更新”强制更新来源；全部更新包括尚未被系统订阅使用的来源，逐条报告结果。更新成功后所有关联订阅在下次访问时使用新数据。
- 每个来源独立更新。某个来源失败时保留它的旧缓存和最近成功时间，不影响其他来源更新。系统订阅可使用失败来源的旧数据与其他来源的新数据组合；任一所选来源完全无缓存且拉取失败时，返回错误，不输出缺少来源的部分结果。
- 修改来源 URL/User-Agent 只使该来源缓存失效；修改名称不影响缓存。修改模板或系统订阅关联后，下次访问按当前配置生成结果，仍有效的来源不重新拉取。
- 同一来源同一配置的并发拉取跨系统订阅合并。编辑前启动的旧更新不会覆盖编辑后的来源缓存。
- 对 `/sub?key=...` 的 HEAD 请求检查链接并输出已有缓存的聚合套餐信息，不触发拉取。

### 来源更新模式

来源新增/编辑时提供“仅手动更新”复选框，默认不勾选，即自动更新。自动模式沿用上述两小时按需缓存策略；勾选后访问或下载系统订阅时只读取已有缓存，过期或 URL/User-Agent 变更后保留的旧缓存也不会触发自动拉取，响应仍通过 `x-subscription-cache: stale` 标记旧数据。完全没有可用缓存时返回 HTTP 409，提示先手动更新该来源。

单条“更新”和“全部更新”在两种模式下都可强制拉取新缓存，全部更新包含仅手动来源；失败仍保留旧数据和成功时间。切换模式不改变缓存 revision 或成功时间，切换前已开始的更新可以正常完成。来源列表在名称下展示模式，旧记录缺少配置时默认自动，更新其他字段而省略模式时保留原选择，无需更换数据目录。不对 403 或其他 HTTP 状态码增加特殊处理、冷却或重试策略。

### 套餐信息

通过一次 GET 同时获取来源的完整订阅正文和 `subscription-userinfo` 响应头，正文与套餐共享同一份缓存和 2 小时有效期，不额外发送套餐探查请求。来源列表仅展示总流量、剩余流量、到期时间，共用现有最近成功时间和更新结果。上游未提供有效套餐字段时显示“未提供”，缺失字段显示“—”；剩余流量需要总量、上传、下载三个字段齐全才能计算，用尽后显示 0。

系统订阅按来源 ID 去重，上传量、下载量、总流量求和，到期时间取最晚值。部分来源无套餐信息时，仅聚合有数据的来源，后台显示“套餐信息覆盖 N/M 个来源”；单个字段缺失时不补零，仅计算已提供的值。所有来源均无数据时不输出套餐头。`total=0` 按无限流量处理，`expire=0` 按长期有效处理；聚合中出现对应特殊值时，聚合结果保留 0。最晚到期时间不代表所有来源均可用至该日期，共享账户的不同来源也可能重复统计额度。

公开系统订阅 `/sub?key=...` 及后台系统订阅下载输出聚合套餐头；第三方来源下载输出其自身缓存的套餐头。HEAD 仅读取已有元数据，不拉取上游。旧缓存没有套餐信息也可继续使用，下一次成功更新后补齐。更新失败保留旧正文和旧套餐；成功返回有效正文但套餐头缺失/无效时，清除旧套餐信息。其他上游响应头不透传，文件名仍使用本系统的“名称-时间戳”。旧 `/sub?url=...` 兼容转换入口保持原有行为。

当前三类模板使用数据格式 v3，不提供旧格式迁移或自动拆分存量模板。检测到旧格式时停止初始化并提示使用新的 `DATA_DIR`；不会修改或删除旧文件。升级时请保留旧数据备份，使用新的数据目录或新的 Compose 数据卷重新维护账号、来源及配置，不要直接删除旧卷。

### 套餐 Webhook 提醒

后台“通知设置”（`#/notifications`）可分别保存钉钉和飞书自定义机器人 Webhook 链接，以及可选签名密钥。可以同时启用两个渠道；链接留空并保存后关闭对应渠道。支持发送测试通知，测试使用已保存配置，不计入正式提醒次数。开启机器人关键词限制时请包含“Mihomo”；开启加签/签名校验时须填写对应密钥。

按第三方来源提醒：套餐在 **3 天内到期或已到期**，或**剩余流量严格小于 30 GB**（1 GB = 1024³ 字节）。两个条件命中时合并发送；消息包含来源名称、官网（已配置时）、剩余流量、到期时间和套餐数据更新时间，不包含订阅链接。缺失套餐字段时跳过对应判断，`total=0` 无限流量不触发流量提醒，`expire=0` 长期有效不触发到期提醒。

每个渠道可选填写一位 **@ 对象**：钉钉填写群成员的手机号；飞书填写群成员的 Open ID（例如 `ou_xxx`）或 User ID，不支持直接填写姓名、手机号或邮箱。配置后正式预警和测试通知都会在消息末尾 @ 此人，留空或清空保存后不 @。目标必须属于机器人所在群，填写有效标识后可用“发送测试通知”检查效果；飞书群自定义机器人本身无法查询成员的 Open ID，需从管理员或具有相应权限的应用获取。可选 @ 配置会随现有设置持久化，修改目标后允许对新目标重新提醒。

预警**仅在对应第三方来源更新成功后**检查该来源的新套餐数据，包含手动更新、全部更新及按需实际拉取成功。服务启动、每小时、保存通知配置、刷新列表或命中缓存均不会扫描已有套餐数据或发送预警；更新失败保留旧缓存，也不触发提醒。来源一成功更新不会触发来源二的旧缓存预警。**到期提醒**按北京时间自然日，同一来源每个渠道每天最多成功提醒一次；**流量预警**在每次来源更新成功后仍低于 30 GB 时即时提醒，不受每日次数限制，数值未变化也会提醒。两个条件本次均需提醒时合并发送。记录重启后保留，发送失败不记为成功，等待下一次该来源更新成功时重试，不影响订阅转换及其他渠道。保存配置或更换渠道链接、密钥、@ 对象后，正式预警仍须等待对应来源下一次成功更新；手动测试通知可随时发送。

每日到期提醒仅在**北京时间 08:00 及之后对应来源首次成功更新**时发送。08:00 后仍须等待该来源下一次成功更新，不保证 08:00 整点发送，也不保证每日必达。08:00 前成功更新且同时命中低流量条件时，只发送流量预警，不消耗当天的到期提醒额度；08:00 后再次成功更新时可单独补发到期消息。前一晚发送跨午夜完成，也不会消耗新一天的早间到期额度。流量预警和手动测试消息不受该时段限制。

通知沿用 Mihomo 节点状态通知的排版：标题保留 ⚠️ 警告图标，字段标签加粗，每个字段独立成段；预警原因同行显示，多个原因用分号连接，官网显示为可点击链接，末尾显示“更新时间：2026/11/3 09:03:59”形式的北京时间。钉钉发送 Markdown 消息，飞书使用红色标题栏的宽屏 Markdown 卡片。流量标题为“Mihomo 流量预警”，到期标题为“Mihomo 套餐即将到期”，同时触发时用“ / ”连接两个标题；测试通知标题为“Mihomo 通知测试”，使用相同格式。

接入格式参考：[钉钉自定义机器人](https://open.dingtalk.com/document/robots/custom-robot-access)、[飞书自定义机器人](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)、[飞书卡片](https://open.feishu.cn/document/feishu-cards/quick-start/send-message-cards-with-custom-bot)。配置链接和密钥保存在现有数据目录中；普通订阅列表接口不返回通知配置，仅登录后的配置接口可读取。

### 第三方订阅请求排查

更新结果中的网络错误会附带经过筛选的底层错误码，帮助区分容器环境问题；不会显示完整 URL、token、节点内容或证书错误详情。

| 错误码 | 排查方向 |
| --- | --- |
| `ENOTFOUND` / `EAI_AGAIN` | 容器内的域名解析、DNS 可用性 |
| `ENETUNREACH` / `EHOSTUNREACH` / `ETIMEDOUT` / `UND_ERR_CONNECT_TIMEOUT` | 容器出口路由、防火墙、上游连接可达性 |
| `ECONNREFUSED` / `ECONNRESET` / `UND_ERR_SOCKET` | 连接被拒绝、连接重置或传输中断 |
| `UNABLE_TO_VERIFY_LEAF_SIGNATURE` / `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` | 上游证书链与容器信任根 |
| `CERT_HAS_EXPIRED` / `CERT_NOT_YET_VALID` | 证书有效期、部署机器系统时间 |
| `ERR_TLS_CERT_ALTNAME_INVALID` | 访问域名与返回证书是否匹配 |

本机浏览器或本地请求成功，不代表容器的 DNS、出口网络和证书环境相同。需要在部署机器的容器内复测，保留 TLS 证书校验。

### 重置用户名 / 密码

容器每次启动会输出随机账号重置 key；进程异常重启时也会轮换。查看日志：

```bash
docker logs -f clash-sub-convert
```

找到最新的 `Account reset key (rotates on startup): ...`，在登录页点击“忘记账号或密码？”，填写该 key、新用户名和新密码。重置后所有已登录会话失效；旧启动 key 无效，订阅链接不受影响。本地运行可直接从启动终端查看 key。

### 数据持久化

`DATA_DIR` 存放账号、来源、模板、系统订阅和缓存。Compose 默认使用 `sub-convert-data` 命名卷，容器重建后保留数据。备份时停止服务并备份整个数据目录；不要执行 `docker compose down -v`，该命令会删除数据卷。自定义绑定目录需允许容器内 `node` 用户（UID 1000）写入。

当前存储面向单进程部署，同一数据目录不能由多个服务实例同时写入。首次初始化期间请自行控制后台访问；公网部署建议通过 HTTPS 反向代理访问。

## 转换规则

- 系统订阅分组名：`国旗 来源名称 大写协议 国家名称`，例如 `🇸🇬 A SS 新加坡`。
- 系统订阅节点名：`国旗 来源名称 国家名称 编号`，例如 `🇸🇬 A 新加坡 01`。
- 同一来源、同一国家/地区跨协议连续编号，名称碰撞时添加消歧后缀。
- 系统订阅分组按国家、来源、协议排序；节点默认保留源内顺序，可按订阅开启偶数节点前置。
- 旧 `/sub?url` 不带来源名称，仍按协议、国家排序，同国家跨协议连续编号。
- 国家识别顺序：国旗、中文名、英文名、独立常见缩写；无法识别时使用 `🏳️ 其他`。
- 协议优先级：`ss → ssr → hysteria2 → trojan → vmess → vless → tuic → hysteria → wireguard → 其他`。
- 国家优先级：`美国 → 日本 → 新加坡 → 其他已识别国家 → 香港 → 台湾 → 其他`。其他已识别国家按中文名称排序。

## 本地运行

需要 Node.js 22 或更高版本：

```bash
npm ci
npm start
```

服务默认监听 `0.0.0.0:25500`。

## API

健康与版本信息：

```text
GET http://127.0.0.1:25500/version
```

转换单个订阅：

```text
GET http://127.0.0.1:25500/sub?url=<URL编码后的订阅地址>
```

合并多个订阅时，先用 `|` 连接地址，再对整个参数值进行 URL 编码：

```text
GET http://127.0.0.1:25500/sub?url=<URL编码后的订阅1|订阅2>
```

兼容 subconverter 风格的调用链接，但 `target` 和其他额外查询参数都会被忽略；输出始终为 Clash.Meta/Mihomo YAML。

成功响应的下载文件名包含当前 Unix 毫秒时间戳，例如 `config-clash-meta-1789353600123.yaml`。

```text
GET /sub?target=anything&url=<已编码地址>&emoji=false
```

抓取上游订阅时固定发送 `User-Agent: clash-verge/v2.4.5`。

## Docker Compose 部署

```bash
docker compose pull
docker compose up -d
```

从当前源码构建并运行：

```bash
docker build -t jiuwusan/z-sub-convert:latest .
docker compose up -d
```

Dockerfile 先复制依赖清单并安装生产依赖，再通过 `COPY . .` 复制源码，源码变化可复用依赖安装层。`.dockerignore` 排除本地依赖、数据、环境配置、密钥、日志、测试和文档，新增运行模块无需再修改复制清单。

镜像基于 `node:22-alpine`，通过 `pm2-runtime` 运行。PM2 的 `max_memory_restart` 设置为 `256M`，进程内存达到阈值后会自动重启。

模板已复制到镜像内的 `/app/prds/template.yaml`，因此默认 Compose 配置不需要挂载模板即可正常使用。

如需在不重建镜像的情况下覆盖模板，可在 `docker-compose.yml` 的服务下添加只读挂载：

```yaml
    volumes:
      - ./prds/template.yaml:/app/prds/template.yaml:ro
```

## 环境变量
