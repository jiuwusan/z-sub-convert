# Source Updates Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans，在当前分支顺序实现；不自动提交。

**Goal:** 第三方来源的最近三天缓存更新持久记录及后台查看。

**Architecture:** 复用 CallRecords 的独立 namespace 和触发方式白名单；Managed 实际更新 finally 追加结果；来源鉴权分页 API 与现有日志弹窗按类型复用。

**Tech Stack:** Node.js 22、JSONL、node:test、原生后台。

**Spec:** docs/superpowers/specs/2026-10-31-source-updates-design.md

## Global Constraints
- 72 小时、无次数上限、日志不影响更新，敏感地址/正文不落日志。
- 自动/手动/全部更新均计入，缓存命中不计入；并发合并只记一次。
- 当前分支，不改变 schema，不自动提交。

## Review Focus
- 命名空间隔离及删除、重启、滚动清理。
- 更新失败保留原缓存；日志写失败不改变更新结果。
- 并发合并、全部更新及配置失效期间失败。
- 鉴权/分页、敏感字段和来源 UA 快照。
- 弹窗类型切换、会话/导航与手机横向滚动。

- 完整测试 86 项通过；新增测试先 RED 后实现。覆盖独立目录、触发方式、缓存命中不记录、合并作业、失败保留缓存、安全字段、旧配置 UA 快照、日志写入失败及来源删除。
- 独立审查无可复现问题；额外验证更新期间删除来源后迟到作业不复活日志，旧配置网络失败不覆盖新配置状态。
