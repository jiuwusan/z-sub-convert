# 订阅后台需求与设计

## 已确认需求
- 独立管理来源：名称、User-Agent（默认 clash-verge/v2.4.5）、HTTP/HTTPS 链接；列表隐藏链接令牌。
- 独立管理模板：名称、YAML textarea，文件上传填入编辑框；验证 proxies、proxy-groups 和 🚀 节点选择、🔰 故障转移 分组的 proxies 数组。首次启动从 prds/template.yaml 创建默认模板，后续不覆盖。
- 系统订阅：名称、有序多选来源、单选模板。列表显示来源名称、模板、缓存状态、最近成功时间、最近结果；复制稳定的 /sub?key=xxx 链接，单条刷新和全部刷新。
- 保存不请求上游。缓存 23 小时，从成功刷新计算；无缓存、过期或配置失效时访问拉取。失败保留旧缓存及成功时间；有旧缓存则返回旧内容，否则报错。多个来源全部成功才替换。
- 来源链接/UA、模板内容、订阅关联修改使依赖缓存失效，名称修改不失效。并发拉取合并；配置变更期间旧刷新不能覆盖新配置缓存。
- 首次无账号直接设置用户名/密码，无需 key；随后用户名密码登录。每次服务启动生成并记录账号重置 key，重置账号时必须校验，旧登录会话失效。订阅 key 不受重启、账号重置影响。
- 数据持久化；保留国家排序和现有转换规则、旧 /sub?url=... 接口。

## 实现选择
沿用原生 Node HTTP + CommonJS + yaml，不引入前端构建链。后台为本地静态 HTML/CSS/JS。单进程 JSON 状态采用串行事务、临时文件原子替换；缓存单独文件，元数据在状态文件，挂载 DATA_DIR。密码使用 scrypt，登录使用 HttpOnly SameSite cookie；管理写接口验证 Origin 和 CSRF token。账号重置 key 只在当前进程内存在，启动日志打印（PM2 异常重启也轮换）。

被引用的来源和模板禁止删除，避免悬空订阅；删除系统订阅会撤销其链接。全部刷新限并发并返回逐项结果。保留旧接口以兼容既有客户端。

## 备选方案
SQLite 增加驱动/版本约束，当前单进程小规模管理采用 JSON 原子事务更贴合原项目。完整前端框架增加构建依赖，此轮使用原生页面。今后多实例部署需要数据库和跨进程刷新锁。

## 验证
使用本地 HTTP 上游验证 UA、合并、TTL、失败回退、刷新并发和配置变更竞态；验证初始化/登录/重置/CSRF、模板校验与重启持久化；保留全部现有测试；浏览器验证初始化到管理操作完整流程。
