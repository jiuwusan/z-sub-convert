# Webhook 套餐提醒

后台新增通知设置，分别维护钉钉、飞书 Webhook 链接和可选签名密钥，留空链接关闭该渠道。管理员可保存和发送测试通知。保持当前分支，无新增依赖，兼容 v3 存量数据。

按第三方来源检查：到期时间在未来 3 天内（含已到期），或者剩余流量严格小于 30 × 1024³ 字节。剩余流量需要 total、upload、download 完整；total=0 无限流量、expire=0 长期有效及缺失字段跳过对应判断。消息包含名称、官网、剩余流量、到期时间和原因，不包含订阅 URL。

采用启动后及每小时读取已有套餐缓存，并在来源成功更新后检查。缓存 revision 不匹配时跳过，过期缓存仍可检查；不额外更新订阅源，保留仅手动更新语义。消息注明套餐数据更新时间。到期提醒按北京时间自然日、来源、渠道配置去重；流量预警按每次成功更新生成的唯一缓存文件、来源、渠道配置去重，每次更新即使流量未变化也提醒，定时检查不重复发送同一缓存的流量预警。首次启用可对已有低流量缓存提醒一次。两种原因本次均待提醒时合并发送。成功记录持久化，失败下次检查重试，渠道失败彼此隔离，不影响订阅服务。

## 方案

仅更新后检查容易漏掉静默来源的到期提醒；定时主动拉取则改变手动更新行为并增加上游访问。因此采用定时检查缓存并结合更新事件。通知配置与发送独立于订阅转换模块。发送限制超时、拒绝重定向，并检查平台业务状态。测试只使用本地假发送器，不向真实群发送。
